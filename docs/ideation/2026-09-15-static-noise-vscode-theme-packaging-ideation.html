Static Noise para VS Code

Empaquetar Static Noise como extensión independiente de VS Code. La paleta y la plantilla aguas arriba siguen siendo la fuente de verdad; este repositorio distribuye temas ya generados.

Grounding Context

El repositorio fuente ya contiene palette.json, templates/vscode.json.template y un compilador que genera dist/vscode/static-noise-color-theme.json. El repositorio destino está vacío. Una extensión de tema debe declarar contributes.themes, incluir los JSON de tema y empaquetarse como VSIX sin compilación al abrir VS Code.

Decisión de alcance: este paquete reutiliza los colores y los tokenColors TextMate existentes. Cualquier trabajo sobre semanticTokenColors pertenece al repositorio Static Noise, no a este consumidor.

I1.

Consumidor mínimo con build reproducible

El repositorio se limita a manifest, documentación, activos del paquete, un script pequeño de Node y themes/. El script toma la paleta y plantilla de una versión fijada de Static Noise y genera el JSON distribuido, sin redefinir hexadecimales ni introducir un segundo sistema de tokens.

I2.

Tema canónico único para la primera versión

La extensión inicial publica solo Static Noise, generado directamente desde la plantilla existente. No intenta resolver OLED, modo suave ni alto contraste antes de comprobar que el contrato de sincronización, empaquetado e instalación funciona de punta a punta.

EJE
Forma inicial del catálogo de temas
BASIS
direct: el upstream dispone de una paleta canónica y una sola plantilla de VS Code.
RATIONALE
Evita que el primer release convierta un empaquetador en un generador de sabores sin una definición de producto.
DOWNSIDES
Los usuarios que quieran otra topología visual tendrán que esperar a una variante deliberada.

I3.

Artefacto generado y guardia contra deriva

El JSON bajo themes/ se versiona y el proyecto añade una comprobación que reconstruye el tema y falla si existe diferencia. Así las revisiones muestran exactamente qué cambiará en el editor y ningún colaborador puede corregir el JSON empaquetado a mano.

EJE
Control de deriva de artefactos
BASIS
external: proyectos como Primer y Catppuccin versionan la salida y verifican que la generación no deje diferencias.
RATIONALE
Protege la fuente de verdad sin obligar al Marketplace ni al editor a ejecutar el compilador.
DOWNSIDES
La contribución exige ejecutar el build antes de actualizar la salida.

I4.

Límite de distribución explícito

El VSIX contiene solamente el manifiesto, licencia, README, icono PNG y los temas generados. .vscodeignore deja fuera scripts, fuentes de compilación, pruebas y configuraciones de desarrollo; un chequeo de preempaquetado revisa tanto el manifiesto como la lista final de archivos.

EJE
Contrato de empaquetado VSIX
BASIS
external: la documentación de publicación de VS Code y vsce valida manifiesto, icono PNG y contenido distribuido.
RATIONALE
Se detectan errores de publicación antes de credenciales o registros externos y el paquete queda pequeño.
DOWNSIDES
Las reglas de exclusión necesitan revisarse cuando se agregue un nuevo activo de runtime.

I5.

Matriz de variantes por roles, no por colores

Después del release canónico, una variante como Void puede reasignar roles de superficie ya existentes —por ejemplo, promover void y reservar surface para elevación— sin modificar los tokens de sintaxis. Las variantes se definen como transformaciones declarativas y se registran como temas separados.

EJE
Forma inicial del catálogo de temas
BASIS
reasoned: la paleta ya diferencia void, surface y card; VS Code permite varios temas por extensión.
RATIONALE
Amplía el catálogo sin bifurcar la paleta ni duplicar la configuración sintáctica.
DOWNSIDES
Debe esperar a que el tema canónico establezca pruebas visuales y una razón clara para cada variante.
CONFIDENCE
76%

I6.

Una VSIX para dos registros

El pipeline de release crea una sola VSIX validada localmente. Esa misma salida se publica, cuando el proyecto esté listo, en Visual Studio Marketplace y Open VSX; las credenciales y reintentos permanecen separados para que un fallo de un registro no cambie el binario ni bloquee el otro.

EJE
Distribución y publicación
BASIS
external: ambos registros aceptan la misma VSIX, aunque exigen cuentas y tokens distintos.
RATIONALE
Cursor, VSCodium y entornos basados en Open VSX pueden instalar el mismo tema publicado para VS Code.
DOWNSIDES
No aporta valor al primer build local; depende de que existan cuentas de publicación.
